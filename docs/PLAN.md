# tokenmate — plan

**End goal:** a TUI chess app where **you bring the model, we bring the chess**.

The 300–2800 Elo ladder is a rule-based engine — search and maths, not a language model. LLMs are opt-in and see the
board through a grounded, schema-validated view, so a model can never invent a move. Ships as `bunx tokenmate`.

Rendered, agreed design: [`relics/tokenmate-design/index.html`](../relics/tokenmate-design/index.html) — boxed 4×3
board, five skins at 3:1, level ladder, architecture.

**Non-goals for v0.1:** accounts, cloud sync, networked multiplayer or spectating, redistributing a chess engine.

The five rules the build enforces are in [ARCHITECTURE.md](ARCHITECTURE.md#invariants).

## Decision: MIT app, engine ships with us (revised 2026-11-21)

| package | version | licence | shipped by us? |
| --- | --- | --- | --- |
| `stockfish` | 19.0.1 | **GPL-3.0** | **no** |
| our own engine (`src/builtin/`) | — | MIT | yes |
| `@opentui/core` | 0.9.7 | MIT | yes |
| `chess.js` | 1.4.0 | BSD-2-Clause | yes |
| `zod` | 4.6.7 | MIT | yes |

**Owner's decision:** tokenmate must be playable with nothing installed, so it ships an engine of our own. Stockfish is
an *optional upgrade*, not a prerequisite. This supersedes the earlier "user supplies the engine" answer: the licence
reasoning was right (we still never redistribute a GPL binary), but making the engine mandatory made the app inert on a
fresh machine.

The built-in is `src/builtin/`: a 0x88 board with alpha-beta search, quiescence, material and piece-square evaluation.
Its movegen is verified against the six standard perft positions (startpos, Kiwipete and four others), which is the only
thing that makes "it plays chess" a checkable claim rather than a hopeful one.

- **It is the default.** `play` uses the built-in unless you name an engine.
- **Resolution order when you do:** `--engine <path or command>` → `$TOKENMATE_ENGINE` → `stockfish` on `PATH` → built-in.
- **A named engine that fails to start is an error**, never a silent substitution back to the built-in.
- **`tokenmate doctor`** reports the built-in's ceiling, whether a UCI engine was found, and the `UCI_Elo` range it accepts.
- **Strength is stated as an estimate.** We have no rated opponent to play a match against, so every built-in level prints
  "estimate", and `doctor` says the same. Above the built-in's ceiling a level says so and points at the fix.
- **No auto-download.** An optional `tokenmate engine install` shells out to the user's own package manager.

### Built-in ceilings, measured

Depth 6 costs 0.9–1.9 s in the middlegame; depth 7 needs 6–8 s, so 6 is the cap and the note says "up to depth N"
because the move clock can stop the search earlier. Estimated Elo by depth: 2→700, 3→1000, 4→1200, 5→1400, 6→1550.

## What we took from chess-tui — and what we refused

[`thomas-mauran/chess-tui`](https://github.com/thomas-mauran/chess-tui) is **GPL-3.0** (1.2k stars, Rust/ratatui, 112
source files). Its code, art and `default_skins.json` **cannot** enter this MIT project. Ideas can, and these are worth
having:

| idea | what we do differently |
| --- | --- |
| `-e /path/to/engine`, including a command *with args* (`-e "gnuchess --uci"`) | same CLI shape — it is the right UX for a user-supplied engine, and it independently confirms the decision above |
| works with **any UCI engine**, not just Stockfish | adopt: the ladder asks the engine what it supports and degrades honestly instead of assuming Stockfish options exist |
| `--difficulty easy\|medium\|hard\|magnus` | **refused.** A level is a level: 1–20, with the Elo it actually plays printed next to it. Named presets are a marketing layer over the same number, and "magnus" is a person's name, not a setting |
| `--depth`, `--no-sound`, resume an in-progress game | adopt |
| `?` helper overlay; arrows **or hjkl**; Space select, Esc deselect | adopt — vim aliases cost nothing and this app is already keyboard-first |
| skins as data (`skin.rs`, `theme_state.rs`) | adopt the idea; our five skins stay *derived* for contrast, not hand-picked RGB |
| PGN viewer, Lichess puzzle mode, Lichess online play, multiplayer server, animations | **post-v0.1 backlog** — except PGN replay, which is v0.1 because it makes the app useful engine-free |

Architecture worth mirroring, concept not code: a `handlers/` dispatcher per screen, and clean splits between
`graphics` / `color` / `constants`.

## Post-v0.1 backlog (deliberately cut)

Lichess **online play** (board API + stream), **puzzle mode**, **networked multiplayer**, move **animations**, sound,
per-skin piece-style editor.

## Measured facts

These are not estimates; each one shaped a decision above.

| fact | value | consequence |
| --- | --- | --- |
| `UCI_Elo` clamp | 1320–3190 | levels 8–19 can use the native option; below 1320 the ladder has to handicap |
| depth 22 | 2.4 s | a full-strength move is affordable interactively at the top level |
| MultiPV 8 | 325 ms | weak-level sampling can ask for eight candidates without a visible pause |
| search speed | ~840k nps | on this machine |
| board at 4×3 | 32×24 cells, piece 8.3% of a square, aspect 1:1.65 | 4×3 was chosen with the numbers in front; see ARCHITECTURE.md |
| lichess `/api/games/user/{name}` | 404 without a User-Agent, 200 with one | always send a descriptive UA |
| models.dev `api.json` | 324 providers, 586 zero-cost models, strong ETag + `must-revalidate` | hourly conditional refresh is effectively free |
| models.dev local coverage | `ollama` absent, `lmstudio` is a 3-model stub | local models must be discovered from the running server |
| toolchain | Bun 1.4.2, Node 25.7.0, macOS arm64 | Stockfish runs under Bun unmodified |
